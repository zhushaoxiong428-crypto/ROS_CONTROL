# 速度控制：测量、调参和没有采用的方案

本文记录速度环从测基线到选定参数的全过程，包括没有效果的尝试，以及过程中发现并修正的测量方法错误。结论和关键数字也汇总在 [README](../README.md#实测结果) 里。所有原始数据都在 `data/` 目录下，可以用 `tools/summarize_steps.py` 重新计算。

## 测试条件和指标

- **场地**：小车放在地上（负载状态）。如无特别说明，每个参数组合都按 ±0.05、±0.1、±0.2 m/s 做阶跃，每档保持 3 秒，两档之间停 1.5 秒。
- **工具**：[tools/speed_step_test.py](../tools/speed_step_test.py) 通过 `/cmd_vel` 发送指令，从 `/odom` 读取车体速度。
- **指标**（[tools/step_metrics.py](../tools/step_metrics.py)）：
  - **t90**：从发出指令到速度第一次达到目标 90% 所用的时间。
  - **稳态误差**：最后 1.5 秒的平均速度相对目标的偏差。
  - **超调**：进入稳态之前的速度峰值超出目标多少。
  - **噪声峰值**：稳态阶段的速度峰值超出稳态均值多少，表示测量噪声的水平。超调要明显高于它才算真正的超调。0.05 m/s 时，每个 20 ms 控制周期只有约 23 个编码器计数，1 个计数就相当于 4% 的速度。
- **重复次数**：最终候选参数每组跑 3 次取平均，交替进行，避免电池压降偏向某一组。单次测量的超调大约有 ±2–3% 的波动。
- **电池电压**：会随电量变化，每组数据都记录了电压，影响见下文。

## 1. 基线：稳态误差 11–15%

板子 NVS 里保存的速度 PID 是 `kp=1.2, ki=0.5`（代码默认值为 `kp=1.0, ki=6`）。落地测试（[data/baseline_20261023_ground](../data/baseline_20261023_ground)）的结果：

| 目标 | 0.25 s 时 | 3 s 时 | 稳态误差 |
| --- | --- | --- | --- |
| 0.05 m/s | 0.045 | 0.047 | -4.4 % |
| 0.10 m/s | 0.085 | 0.091 | -10.8 % |
| 0.20 m/s | 0.152 | 0.175 | -14.7 % |
| -0.10 m/s | -0.082 | -0.092 | -11.1 % |

速度在 0.25 s 内冲到目标的约 85%，之后就慢慢往上爬，0.1 m/s 要 2.1 s 才到 90%。原因是积分作用太弱。**架空测试看不出这个问题**：没有负载时，比例项单独就几乎够用；反过来，架空时低速波动有 12%，落地后只有 2%，地面摩擦起了阻尼作用。所以后面的评估都以落地数据为准。

## 2. PID 调参

先扫 `ki`（`kp=1.2`，[data/ki_sweep_20261023_ground](../data/ki_sweep_20261023_ground)），再扫 `kp`（`ki=6`，[data/kp_sweep_20261023_ground](../data/kp_sweep_20261023_ground)），最后做 3×3 网格（[data/pid_grid_20261023_ground](../data/pid_grid_20261023_ground)）。下表中“低速超调”是 ±0.05 和 ±0.1 m/s 四档的平均值，括号里是对应的噪声峰值：

| 参数 | 低速超调 | 最大稳态误差 | 说明 |
| --- | --- | --- | --- |
| `kp=1.2, ki=0.5` | 0.0 % (4.9) | 15.1 % | 基线，响应太慢 |
| `kp=1.2, ki=2` | 1.8 % (6.1) | 2.3 % | |
| **`kp=1.2, ki=4`**（3 次平均） | **3.9 % (2.8)** | **0.9 %** | **选定**，t90 为 180–269 ms |
| `kp=1.2, ki=6`（3 次平均） | 10.0 % (3.2) | 0.6 % | t90 为 173–191 ms |
| `kp=1.2, ki=12` | 29.8 % (5.6) | 0.4 % | |
| `kp=2 / 3 / 4, ki=6` | 14.1 / 16.6 / 23.8 % | ≤ 1.6 % | `kp` 越大，超调越大 |
| `kp=0.6 / 0.9, ki=6` | 18.0 / 16.5 % | ≤ 1.3 % | `kp` 往小调也会变差 |

- **`ki` 是在超调和响应速度之间取舍**：`ki` 越小，超调越小，响应越慢。
- **`kp=1.2` 刚好是超调最低的位置**。速度环用的是增量式 PID，比例项作用在误差的变化量上。阶跃到来时，它会一次性加上 `kp × 目标变化量`，所以 `kp` 越大，起步冲得越猛。
- **选择标准是事先定好的**：稳态误差 < 1%、t90 < 250 ms，然后选低速超调最小的组合。按这个标准，`ki=6` 胜出，因为 `ki=4` 在 -0.2 m/s 时 t90 为 269 ms。最后选了 `ki=4`，理由是低速超调降了一半多，而 t90 最多只慢了约 100 ms（-0.2 m/s 时 269 对 173 ms）。这是有意识的取舍，不是为了凑结果去改标准。

选定的 `kp=1.2, ki=4` 已经写成代码默认值，也保存进了小车的 NVS。

**电池电压的影响**：同样是 `kp=1.2, ki=4`，在 7.4 V 时低速超调为 3.9%（噪声 2.8%），在 7.98 V 时为 8.0%（噪声 4.3%）。电压越高，同样 PWM 下电机越快，相当于控制对象的增益变大了。

## 3. 电机特性

用诊断版固件做开环测量（`CONFIG_LEAP_MOTOR_CHARACTERIZATION`，通过 `/cmd_vel` 的 `linear.z` / `angular.x` 直接下发 PWM；工具是 [tools/motor_characterization.py](../tools/motor_characterization.py)）。在 PWM 150–200 范围内，每档保持 2 秒、电机已热机，得到的结果（[data/motor_characterization_20261024_warm](../data/motor_characterization_20261024_warm)）：

| 轮 | 死区 p0（PWM，满量程 255） | 斜率 | 方向差异 |
| --- | --- | --- | --- |
| 左 | 142.5 | 5.96 mm/s 每 PWM | 前进和后退的斜率相差 0.2%，死区相差 0.4 PWM |
| 右 | 143.1 | 5.94 mm/s 每 PWM | 前进和后退的斜率相差 2.9%，死区相差 0.3 PWM |

- **两个电机、两个方向的特性几乎一样。** 所以后退响应比前进慢，不是电机不对称造成的。
- 代码里固定加的死区补偿是 150，比实测死区约高 8 个 PWM。
- 满 PWM（255）时速度约 0.62 m/s；200 以上曲线开始向下弯。

第一次测量（[data/motor_characterization_20261024](../data/motor_characterization_20261024)）有三个问题，后来重测时都改正了：每档只保持 1.2 秒，PWM 150/160 还没有稳定（最后 0.4 秒里仍上升了 16–19% / 6–7%）；拟合范围用了 150–255，把高速段的弯曲也算了进去，斜率偏低（同一组数据只拟合 160–200 时，斜率是 5.87，而不是 5.62）；±180 这两个点比相邻点低约 10%。当时我推测偏差来自“电机发热”，但在已经稳定的档位上，凉机和热机只差约 3%，大部分偏差其实来自测量方法。

## 4. 试过但没有采用的方案

### 速度前馈

按电机曲线直接给出 PWM：`PWM = (p0 + |v|/k) × V_ref / V_电池`，PID 只负责修正剩下的误差，并且限制在 ±60 PWM 以内（[main/control/wheel_feedforward.h](../main/control/wheel_feedforward.h)）。数据见 [data/feedforward_20261024](../data/feedforward_20261024)：

| 方案（7.9 V） | 低速超调（噪声） | 0.1 m/s 超调 | 最大稳态误差 |
| --- | --- | --- | --- |
| 纯 PID `kp=1.2, ki=4`（7.98 V） | 8.0 % (4.3) | 3.0 % | 1.0 % |
| 纯前馈（`kp=ki=0`） | 4.6 % (5.5) | 4.0 % | 5.3 % |
| 前馈 + `kp=1.2, ki=1` | 8.4 % (3.8) | 7.7 % | 2.4 % |
| 前馈 + `kp=1.2, ki=2` | 10.9 % (3.5) | 10.6 % | 1.9 % |

前馈本身不超调，0.1 m/s 以上稳态偏差在 3.4% 以内；但纯前馈的 t90 要 0.4–0.9 s，基本就是电机自身的加速时间。加上 PID 来加快响应后，电机还在加速的那段时间里误差一直很大，积分项持续累积，最终 0.1 m/s 出现 8–11% 的真实超调，比纯 PID 更差。前馈带来的好处只是大幅阶跃更快一些（-0.2 m/s 时 t90 从 188 ms 降到 141–154 ms）。代码默认关闭前馈（`kUseSpeedFeedforward = false`），需要时可以在运行时打开。

### 10 位 PWM

在实验分支 `exp/pwm-10bit` 上，LEDC 改为 10 位，控制器沿用 0–255 的单位，只是保留小数。同一电压下各跑 3 次：低速超调 8 位为 7.0 / 8.4 / 8.6%，10 位为 9.9 / 10.0 / 9.9%；0.05 m/s 的波动 8 位为 3.2–3.9%，10 位为 4.6–5.0%。两组没有重叠，10 位略差。

分辨率并不是瓶颈：积分项会让输出在相邻两档之间来回切换，电机惯性又会把它平均掉。10 位反而变差，可能的原因是：去掉了原来向零截断带来的约 0.5 PWM 偏差，满量程又从 255/256 变成了 255/255，合起来让死区补偿实际多推了约 1 PWM。这个原因没有单独验证。没有合并进主线。

### 目标速度斜坡

在速度模式下，目标速度按设定的加速度逐渐上升（[main/control/velocity_ramp.h](../main/control/velocity_ramp.h)），零速指令依然立即停车。数据见 [data/velocity_ramp_20261024](../data/velocity_ramp_20261024)，每种各跑 1 次：

| 加速度上限 | 无（阶跃） | 0.5 m/s² | 1 m/s² | 2 m/s² |
| --- | --- | --- | --- | --- |
| 纯 PID，低速超调 | 5.4 % | 3.2 % | 7.0 % | 4.9 % |
| 前馈 + PID，低速超调 | 10.0 % | 11.0 % | 12.4 % | 12.0 % |

纯 PID 的超调本来就在噪声水平（4–6%），斜坡没有可改善的空间；前馈的超调来自积分累积，而不是起步冲击，所以斜坡也压不下去。斜坡默认关闭（`kDefaultVelocityAccelLimitMps2 = 0`）。

前馈和斜坡都可以在运行时开关，不用重刷固件，也不写进 NVS：

```bash
curl -X POST http://<小车IP>/api/motion-tuning --data 'feedforward=1&accel_mps2=1.0'
```

## 5. 过程中修正过的错误

- **超调指标**：最初的超调是整个 3 秒里的最大值，在 0.05 m/s 时主要反映的是编码器量化噪声。纯 PID 在 0.1 m/s 时，进入稳态前的峰值其实只有 0–1%，却被报成了 3–5%。修正后，所有已保存的数据都重新算了一遍：选 `ki=4`、前馈和 10 位 PWM 没有改善，这几条结论都没变；但原先以为纯前馈超调 16%，实际只有 4.6%，在噪声范围以内。
- **电机特性测量**：保持时间太短、拟合范围选错，见第 3 节。
- **里程计**：1 m 直行三次的实测值都记成了整数“100 cm”，因此得出“里程计多算 1.7%”。改用 1.5 m、量到 0.5 cm 后，偏差只有 0.15%，轮径不需要修正（[data/odom_calibration_20261024](../data/odom_calibration_20261024)）。
- **控制循环定时**：原本推测 `vTaskDelay` 会让周期漂移。实测周期均值正好 20.000 ms，因为任务总是在 10 ms 的 tick 上被唤醒，而每轮只执行 0.3 ms。改用 `vTaskDelayUntil` 只是让代码在负载变大时也稳健；实测 `dt` 用来修正约 1 ms 的唤醒抖动（[data/loop_timing_20261023](../data/loop_timing_20261023)）。

## 6. 还没解决的问题

- **低速测速噪声**：0.05 m/s 时噪声约 4%，这是目前低速表现的下限。可以考虑改用测量编码器脉冲间隔的方式来估算速度。
- **后退大幅阶跃更慢**：电机已经排除，原因还没找到。
- **电压影响**：参数是在 7.4–8.0 V 之间调出来的，电池电量很低时没有测过。

## 复现

```bash
source /opt/ros/humble/setup.bash
python3 tools/speed_step_test.py --speeds 0.05,-0.05,0.1,-0.1,0.2,-0.2 --hold-s 3 --csv run_r1.csv
python3 tools/summarize_steps.py data/pid_grid_20261023_ground/*.csv
```

调 PID 用 `/set_speed_pid` 服务（会写进 NVS）。服务类型在 `extra_ros_packages/leap_interfaces` 里，需要先在电脑上用 `colcon build` 编译。
