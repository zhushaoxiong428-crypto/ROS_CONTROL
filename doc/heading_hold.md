# 直行航向保持

## 问题

落地直行时，车在 0.05–0.2 m/s 各速度下都会明显向左偏。原有控制只基于编码器：

| 原因 | 编码器能否看到 | 原控制能否纠正 |
| --- | --- | --- |
| 同步 PI 的 ±0.5 rpm 死区：积分只累计死区外的误差，残留速度差约 0.74°/s 持续偏航 | 能 | 否 |
| 起步阶段同步积分冻结：起步几百毫秒内累积的航向差（架空数据约 2.7°）不回补 | 能 | 否 |
| 左右轮径差、打滑 | 否 | 否 |

编码器同步的目标是"两轮转得一样快"，而真正要控制的是"车头朝向不变"。

## 方案

直行命令（`angular.z == 0` 且 `linear.x != 0`）开始时锁存 IMU 航向作为参考，之后每个 20 ms 周期：

```text
e    = wrap(yaw_ref - yaw_imu)
wz   = clamp(Kp*e + Ki*∫e, ±0.35 rad/s)          // 条件积分抗饱和
Δrpm = clamp(wz * (轮距/2) * mm/s→rpm, ±30% × 平均目标转速)
left_target  -= Δrpm
right_target += Δrpm
```

- 修正作用在目标转速上，最终目标不变，所以轮对控制器仍按直行判定，起步辅助与同步 PI 照常工作。
- ±30% 的限幅避免在起步斜坡低速段把一侧目标推到反方向。
- 转弯、停车、急停、里程计复位都会复位参考航向；下一段直行重新锁存。
- 默认 `Kp = 1.5 /s`、`Ki = 0.5 /s²`，闭环时间常数约 0.7 s。
- `idf.py menuconfig → Leap low settings → Hold IMU heading while driving straight` 可关闭，用于 A/B 对比。

实现：[`heading_hold.h/.cpp`](../main/control/heading_hold.h)，主机测试 [`heading_hold_test.cpp`](../tests/heading_hold_test.cpp)（含恒定 2.9°/s 扰动下 30 s 稳态误差 < 0.3° 的闭环仿真）。

## 实测：左右轮行程比例差（2026-09-28）

开启航向保持后的第一批落地数据（1 m 直行指令）：

| 速度 | IMU 航向变化 | 编码器航向变化 | 推算右/左行程比 |
| --- | ---: | ---: | ---: |
| 0.1 m/s | −1.34° | −21.22° | 1.0531 |
| 0.2 m/s | −0.12° | −20.52° | 1.0553 |

车头被航向保持拉直了，编码器却推算出约 20° 的右转：右轮每个编码器脉冲实际走得比左轮远约 5.4%。
速度翻倍比例几乎不变，说明是固定的减速比/轮径差，而不是打滑。这正是原来"编码器转速相等、车却一直左偏"的主因，
同时也让 `/odom` 在直线上错报约 20° 转弯。

标定：`idf.py menuconfig → Leap low settings → Right/left wheel travel per encoder count ratio`，
本车取两次均值 `10542`（×10000）。系数按均值不变拆到左右两侧，只修正左右差、不改变整体距离标定。
重新标定时，用 `tools/straight_drive_test.py` 输出的 `right/left ratio` 乘以当前值即可。

起步瞬间（开始运动后约 0.1 s）IMU 已向左转约 2° 而编码器几乎无变化，这部分来自起步时的打滑或万向轮转向，
编码器看不到，仍由航向保持纠正。

## 验证方法

车放地上，前方留 1.5 m 以上空间，手放在急停上：

```bash
source /opt/ros/humble/setup.bash
python3 tools/straight_drive_test.py --speed 0.1 --distance 1.0 --confirm-ground
```

脚本同时记录 `/odom`（编码器航向）和 `/imu`（陀螺仪航向），输出偏航角、侧向偏移，并判断偏航来源：

- 编码器也看到了大部分偏航：左右轮转速确实不同（控制问题）；
- 编码器几乎没看到：轮径差或打滑（机械问题）。

A/B 步骤：关闭航向保持的固件与默认固件，在 0.05 / 0.1 / 0.2 m/s 下各跑 3 次 1 m。

验收判据（默认固件）：1 m 直行 IMU 航向变化 `|Δψ| < 2°`，侧向偏移 `< 3 cm`。

注意：侧向偏移来自 `/odom`，机械原因造成的偏航在编码器里看不到，此时应以 IMU 偏航角和卷尺实测为准。
